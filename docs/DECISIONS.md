# Decision Log

## ADR-001 — 3D вместо исходного 2D (2026-10-31)
Источник: ответ пользователя «Вариант 1, но 3D». Сохраняем спасение паучат и стелс, создаём реальный WebGL-мир. Стек Three.js без игрового редактора отвечает конкурсным ограничениям. Альтернатива Phaser отклонена как 2D.

## ADR-002 — Отдельная модель, статическое размещение
Игра однопользовательская, без аккаунтов и платного контента. Хранение локальное с валидацией и fallback. Сервер, авторизация, админка и платежи не добавляются без потребности. Это не заглушка backend: сетевой backend отсутствует по согласованному замыслу.

## ADR-003 — Локальные ассеты (обновлено 2026-10-31)
Изначально модели создавались кодом. По запросу пользователя и утверждённому плану персонажи заменяются анатомическими glTF с проверенной свободной лицензией; окружение и звук остаются процедурными. Все файлы входят в сборку: без сторонних запросов и сетевых шрифтов. Sketchfab-кандидаты оставлены как источники исследования: без авторизации официальные загрузки недоступны, viewer-cache и обход входа не применяются. Внедрены WebXR Input Profiles generic-hand (MIT) и открытый Spider от sunburn (CC BY 3.0). Паук оптимизирован, оснащён восьминогим скелетом и поверхностной пигментацией; кисть привязана к фактической ладонной поверхности. Источники и изменения записаны в public/models/SOURCES.json и THIRD_PARTY_LICENSES.txt. Геометрия, независимость скелетов и крупные планы проверены.

## ADR-007 — Контакт руки и спутники принадлежат симуляции
Фиксированная временная шкала и одна геометрия опасной области вместо покадрового lerp и несвязанного круга урона. Регрессия до исправления: 4 из 5 новых тестов руки падали (урон до видимого контакта, невозможность отменить опускание паутиной). Позиции малышей перемещаются в game/followers.js; у каждого безопасная очередь пути ведущего. Полноценный физический движок для плоского стола не добавляется; коллизии и поза проверяемы без WebGL. Счётчик детей и условия победы не меняются.

## ADR-008 — Атомарное наблюдение удара и опорная геометрия (2026-10-31)
Браузерная диагностика `artifacts/hand-diagnosis.json` зафиксировала три естественных контакта с неподвижным пауком: здоровье 3→2→1→0. Между `waitForFunction(strike)` и отдельным `evaluate(snapshot)` короткая фаза могла завершиться; тест ошибочно считал поздний кадр началом удара. Теперь наблюдатель RAF сохраняет фазу, здоровье и отрисованную позу атомарно в странице, без записи в состояние.

Крупный план выявил реальную проблему поверхности: привязка к минимуму bounding box кисти не совпадала с ладонью, цилиндр предплечья заходил в стол, ладонь проходила сквозь спину. Добавлены red-тесты фактической поверхности и высоты контакта. Кисть имеет подготовленную опорную позу, raycast ладони и loft запястья; симуляция останавливает её на спине (0.54), при промахе — на столе (0). Поза восстановления начинается с предыдущего curl, без скачка. Упрощённая 2.5D-коллизия сохранена: полноценный rigid-body engine не требуется.

## ADR-009 — Ориентация кисти относительно стола (2026-10-31)
По замечанию пользователя ладонь была видна сверху. Локальная GLB-кисть перевёрнута вокруг продольной оси пальцев: ладонь направлена к столу/пауку, тыл — к камере. Опорная точка сохраняется на нижней реальной поверхности, область предупреждения и попадания отражена по X вместе с большим пальцем. Переворот только камеры отклонён: в игре он оставил бы удар неверной стороной кисти.

## ADR-010 — Направленное движение руки и большая семья (2026-10-31)
По запросу пользователя добавлено по три паучонка в каждую главу: 6/7/8 вместо 3/4/5. Исходные точки сохранены, новые включены в проходимые маршруты; время глав не менялось. Победная расстановка теперь зависит от размера семьи и не сближает восьмого малыша с первым.

От декоративного скольжения сразу к warning перешли к отдельному track: человек заметил паука, разворачивает предплечье и подводит кисть к текущей позиции. Скорости подвода и поворота ограничены; минимум 0.95 с до фиксации. Янтарная метка и HUD показывают наведение. В warning x/z/angle фиксируются, замах предшествует контакту; постоянное преследование в самой фазе удара отклонено как не дающее увернуться. Общая повернутая область пальцев/ладони служит и предупреждению, и урону; ладонь остаётся вниз. Укрытие срывает track, паутина направляет руку к приманке. Полную модель тела человека не добавляем: действие читается через кисть, предплечье, замах и реакцию на цель.

TDD: до реализации пять профильных проверок упали (число малышей, фаза наведения, поворот модели и коллизий). После реализации и расширения регрессий прошли 40/40 модульных тестов; приёмка браузера записывается отдельно в QA_REPORT.

## ADR-004 — Ограничение Git и публикации
`git rev-parse --show-toplevel` вернул `D:/`, а не папку игры. Не выполнять массовое git add/commit/push и не публиковать общий репозиторий. Безопасный артефакт — dist и архив только файлов релиза. Публикация требует доступного назначения; отсутствие инструмента не подменять фиктивной ссылкой.

## ADR-011 — GitHub Pages и изолированная Git-история (2026-10-31)
Пользователь выбрал GitHub Pages из вариантов размещения. Инициализирован новый репозиторий непосредственно в папке игры; `git rev-parse --show-toplevel` подтвердил `D:/Development/Sharrowkin_game2`. Это не копирование или публикация общего репозитория диска. Исходники и локальные GLB нужны для воспроизводимой CI-сборки; рабочие артефакты/видео, dist, окружения, настройки IDE и секреты игнорируются.

Официальные GitHub Docs и action.yml проверены перед настройкой. Workflow использует checkout v6, setup-node v6, configure-pages v5, upload-pages-artifact v4, deploy-pages v5. Сайт собирается по lockfile, тестируется и публикуется только из dist. Отдельные тесты перед реализацией подтвердили отсутствие валидатора; затем добавлен check-pages-build с негативными сценариями для пропавших моделей, абсолютных/внешних путей и лишних файлов. Ручной workflow_dispatch предусмотрен для первого запуска после включения Pages. Персональный токен не добавляется; встроенного GITHUB_TOKEN достаточно после настройки Pages. Наличие workflow не принимается за состоявшийся деплой. На GitHub Free пользователь меняет видимость отдельного репозитория на public через GitHub; платные услуги не подключаются.

## ADR-005 — Документация и TDD
Context7 есть в списке MCP, но его tools не доступны текущей сессии. Использовать проверенные официальные docs и исходники фиксированного тега, отметить ограничение. Node-тесты создаются и запускаются до реализации модели; браузерные сценарии — до UI.

## ADR-006 — Производительность на software Chromium
Наблюдались GPU ReadPixels stalls и таймауты e2e. Перед оптимизацией добавлены red-тесты batching и лимита draw-объектов; после неё 17 unit-тестов green. Неподвижная геометрия объединена, лапы — InstancedMesh: кадр первого уровня снизился примерно со 190 до 54 draw calls. Статические тени 1024², адаптивное разрешение и ограничение рендера за модальными окнами устранили таймаут сценария клавиатуры. Бизнес-правила и интерактивное прохождение не упрощались.
