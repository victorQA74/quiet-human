# Technical Specification

## Стек и ограничения
- Node.js >=22.12.0 (фактически 22.23.2), npm 11.10.0.
- Three.js 0.187.0, Vite 8.3.5, vanilla JavaScript ES modules.
- Node built-in test runner для модели; Playwright 1.64.1 для реального Chromium и видео.
- WebGL2; при невозможности создать renderer показывается понятное сообщение.
- Статический `dist/index.html`, относительный base `./`; все зависимости в локальном bundle.

## Разделение ответственности
- `src/game/levels.js`: декларативные главы, препятствия, укрытия, старт, дети, выход, параметры опасности.
- `src/game/navigation.js`: проверка столкновений, A* по ограниченной сетке для клика/касания.
- `src/game/model.js`: состояние, фиксированные шаги, перемещение, дети, укрытие, внимание, фазы руки, приманки, таймер, исход.
- `src/game/storage.js`: версия и валидация локального прогресса, безопасные чтение/запись, рекорды.
- `src/view/scene.js`: Three.js-сцена, камера, свет, визуализация модели, raycasting.
- `src/view/objects.js`: процедурные предметы и окружение; повторное использование материалов/геометрии.
- `src/game/hand.js`: траектория кисти, интервалы контакта и единые области столкновения/предупреждения.
- `src/game/followers.js`: следование и безопасные позиции паучат.
- `src/view/assets.js`: локальная загрузка glTF через GLTFLoader, проверка скелета и обработка ошибки/повтора.
- `src/view/characters.js`: независимые SkeletonUtils.clone, позы кисти и походка пауков. SkinnedMesh и их иерархии не объединяются batchOpaque.
- `src/input.js`: клавиатура, pointer events, джойстик, камера; выдаёт намерения, не меняет бизнес-правила.
- `src/audio.js`: Web Audio, синтез звуков после жеста пользователя, отключение по настройке.
- `src/ui.js`, `src/main.js`, `src/style.css`: экраны, доступность, жизненный цикл, сохранение победы.

## Модель и API (внутренний, без сетевого сервера)
`createGame(levelIndex)` создаёт новую сессию. `stepGame(state,input,dt)` меняет модель только в статусе playing. `startGame`, `pauseGame`, `setDestination`, `castWeb` — команды с валидацией.

Состояние: `status`, `levelIndex`, `elapsed`, `remaining`, `player:{x,z,angle,health,invincible,hidden,moving}`, `babies:[{id,x,z,rescued}]`, `path`, `rescued`, `silk`, `silkClock`, `webs`, `hand:{phase,timer,attention,target,scan}`, `score`, `stars`, `reason`, `events`.

Фазы руки: search → track → warning → strike → recover → search; приманка переключает в distracted до окончания отвлечения. Во время track человек ведёт цель по текущим координатам паука: скорость подвода ограничена 18 единиц/с, поворот 3 рад/с, минимальное время наведения 0.95 с. Поворот yaw вычисляется от условного положения человека (0, −16) за дальним краем стола. В warning можно перейти только при расстоянии ладони до цели <0.55 и ошибке угла <0.055 рад. Вход в укрытие срывает track; в distracted внимание остаётся нулевым. Кисть и предплечье разворачиваются вместе вокруг контактной точки, ладонью вниз. Янтарная метка показывает подвижную цель, красная — фиксированные x/z/angle до конца удара; warning включает короткий подъём-замах 0.65 единицы. При коллизии координаты паука поворачиваются в локальную систему кисти; scene.warning получает тот же yaw, поэтому повернутые пальцы не создают отдельной невидимой зоны. `game/hand.js` задаёт единую временную шкалу: 0.24 с опускание до контакта, 0.14 с удержание, 1.5 с восстановление. Урон только при пересечении времени контакта, с `contacted`-защитой от повтора; `hand.pose` хранит x/y/z, angle и curl в модели. Рендер не интерполирует позицию по кадрам. Центр контакта ладони совпадает с target: при промахе y=0 на столе, при пересечении открытого тела — y=0.54 (высота спины GLB), чтобы центральная ладонь не проходила сквозь паука. Это управляемая 2.5D-аппроксимация, не mesh-to-mesh/soft-body контакт кожи под каждой фалангой. Высота фиксируется в момент контакта до конца удержания; curl плавно восстанавливается из предыдущей позы. Общие локальные области ладони/пальцев используются предупреждением и столкновением с кругом тела паука (radius 0.34). Укрытие защищает; паутина до контакта отменяет атаку, после контакта не возвращает здоровье. Нормализованный вектор движения исключает ускорение по диагонали.

Главы содержат 6/7/8 малышей (добавлено по три). Позиции, направление, флаг движения и порядок подбора паучат принадлежат игровой модели. Победная расстановка равномерна по числу малышей, с проверкой проходимости и интервала >0.4; старый шаг по 20 слотам непригоден для восьми. Ведущий цепочки — предыдущий спасённый малыш; каждый сохраняет безопасный пройденный маршрут ведущего, двигается с дистанцией и коллизиями. Рендер читает эти позиции; победа собирает семью у гнезда без изменения счётчика. Малыши не получают самостоятельный урон.

Навигация: стол 24×18 условных единиц, круг героя радиуса 0.34; столкновения с кругами и прямоугольниками; расширение препятствий радиусом героя; ограниченная сетка A*. dt модели ограничен 0.05, игровой цикл использует фиксированный 1/60 и максимум 5 шагов за кадр. При уходе со вкладки — пауза.

## Данные
`localStorage['quiet-human.progress.v1']`: `{version:1,unlocked:1..3,best:[{score,stars,time}|null]×3,settings:{sound:boolean,reducedMotion:boolean},tutorialSeen:boolean}`. Чужой HTML не вставляется из сохранения. Неизвестные поля игнорируются; конечность, диапазоны и типы проверяются. Ошибки JSON и SecurityError/QuotaExceededError перехватываются. Никаких секретов.

## Рендер и производительность
Один WebGL canvas, ортографическая обзорная камера с поворотом Q/E, правой кнопкой и сбросом C. Общий вид обеспечивает обзор игрового поля. Окружение — процедурные примитивы, общие материалы; статические непрозрачные части объединены через BufferGeometryUtils.mergeGeometries с vertexColors. Персонажи — локальные GLB SkinnedMesh, по 3 примитива у паука и 1 у кисти; независимые скелеты через SkeletonUtils.clone. Лапы анимируются костями (прежний InstancedMesh больше не используется). Кисть развёрнута вокруг продольной оси пальцев ладонью вниз; оси сгибания вычисляются по направлению фаланг, область предупреждения/коллизии зеркально соответствует положению пальцев и большого пальца. Кисть укладывается в контактную позу; нижняя поверхность ладони определяется raycast снизу, предплечье строится loft по контуру запястья. Ограниченные частицы, без одного DOM-узла на 3D-объект. Pixel ratio ограничен 1.75 (1.25 на телефоне) и автоматически снижается до 0.55 при <28 FPS. Одна статическая карта теней PCFShadowMap 1024², без тяжёлого постпроцессинга. Под модальными окнами рендер ограничен 4 FPS, в меню 20 FPS; симуляция на паузе не идёт. Три группы уровней кэшируются (ограниченный кеш), временная геометрия приманок освобождается.

## Проверка и TDD
Сначала написать тесты модели/навигации/хранилища, запустить и зафиксировать red из-за отсутствующего кода; затем реализация и green. UI-сценарии также создаются до UI-кода. Для e2e допускается только read-only диагностика в dev/test (`snapshot`, `project`); запрещены команды победы, телепортации и неуязвимости. Прохождение выполняется pointer/keyboard через реальный input и step loop. В production диагностический интерфейс отсутствует.

## Источники и инструменты
Проверены npm registry (точные версии/engines), официальное руководство Vite, официальная документация Playwright и исходник WebGLRenderer тега r187. Context7 подключён в проекте, но его query-docs/resolve-library-id не предоставлены в текущем списке инструментов. Недоступность MCP не выдаётся за выполненный запрос. Часть старых URL manual Three.js вернула 404; API сверяется с версионным исходником/npm-пакетом.
